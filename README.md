# Ответ на сообщение: прототип формы

Демо: https://nikolayyaroslavcev.github.io/reply-tool-prototype/

Прототип к тестовому заданию. Форма подбора ответа на сообщение (текст, тон, три варианта), в которой каждое состояние описано явно. Сервер замокан: на странице можно выбрать сценарий ответа и посмотреть загрузку, ошибку сети, таймаут и лимит 429.

## Что решает

- Варианты привязаны к запросу. Новый запрос или ошибка убирают старые варианты, поэтому под новым сообщением не остаются ответы к прошлому.
- Повторная отправка отменяет прошлый запрос через `AbortController`, а опоздавший ответ отбрасывается по id в reducer.
- Если после ответа поменяли текст или тон, варианты бледнеют, кнопка меняется на «Обновить варианты».
- После ответа список прокручивается в зону видимости, фокус переходит на первый вариант.
- «Скопировано» показывается только у последнего скопированного варианта и гаснет через 2 секунды.
- На 429 кнопка ждёт `Retry-After` с обратным отсчётом.

## Устройство

- `src/tool/state.ts`: состояние как размеченное объединение (`idle | loading | done | error`) и reducer.
- `src/tool/api.ts`: мок API со сценариями и таймаутом через `AbortSignal.any`.
- `src/tool/ReplyTool.tsx`: форма, эффекты прокрутки, копирования и обратного отсчёта.
- Тесты: `state.test.ts` (reducer) и `ReplyTool.test.tsx` (ошибка после успеха, гонка запросов, смена тона).
